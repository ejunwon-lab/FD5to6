원본이 있는 데이터를 지시문·코드·설정·문서에 **글자로 따로 적어 두지 않는다**. 필요한 쪽이 실행 때마다 원본에서 읽게 설계한다.

**Why:** 2026-11-16 — KR·주간 리포트 지시문에 보유 종목 목록을 손으로 적어 둔 탓에, 사용자가 매매를 GAS에 다 기록했는데도 리포트는 약 4개월간 이미 판 3종목을 보유로 다루고 새로 산 1종목을 빠뜨렸다. 11/14에 어긋남을 발견하고도 두 목록의 합집합으로 덮어 원인(사본)을 남겨 둔 것이 두 번째 잘못. 사용자 지시: "앞으로는 이런 설계 오류가 없도록 해."

**How to apply:**
- 새 기능·지시문·스크립트를 만들 때 "이 값의 원본이 어디 있나? 사용자가 원본을 바꾸면 이것도 저절로 바뀌나?"를 먼저 묻는다. 저절로 안 바뀌면 설계 오류 — 코딩 전에 고친다(`/design-check` 노트에 한 줄로 명시).
- 대상 예: 보유 종목·종목 수·계좌·분류·휴장일·임계값처럼 시트/GAS에 원본이 있는 것. 지시문 출력 틀에 실제 종목명을 박는 것도 사본이다.
- 원본 무응답 대비 사본이 꼭 필요하면 **기계가 성공할 때마다 덮어쓰는 캐시**로만 두고, 캐시를 썼다는 사실을 결과물에 드러낸다.
- 사람이 써야만 하는 것(투자 논리 등)은 자동화 대신 **어긋남을 결과물에 드러내는 검사**를 붙인다(예: "논리 미등록 n종목").
- 어긋남을 발견하면 사본끼리 맞추거나 합치지 말고 사본을 없앤다. 발견 즉시 사용자에게 원인까지 말한다.

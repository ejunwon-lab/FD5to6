사용자가 받는 리포트·알림(텔레그램 등)은 **맨 위 요약만 읽어도 끝나게** 쓴다: 무슨 일이었나 한 줄 → 내 숫자 → 왜 → **그래서 뭘 할지(최대 3줄)**. 근거·표는 뒤로(별도 메시지) 보낸다.

**Why:** 2026-11-16 사용자: "리포트가 너무 복잡해서 읽기가 힘들어. 두괄식으로 하루를 요약하는 부분을 강화해. 한눈에 그날의 상황을 파악하기 쉽고, 그래서 뭘 해야겠다는 생각을 하게 유도하란 말이야." / "빨간불은 뭔가 정말 내가 어텐션해야하는구나라고 생각하도록 만들 때 사용해." 같은 날 아침 리포트는 AI가 숫자를 직접 계산하다 방향이 반대인 값을 내보냈다.

**How to apply:**
- 리포트·알림 문구나 지시문을 만들고 고칠 때: 첫 줄에 결론, 한 줄에 숫자 2개까지, 증권가 용어·영어 약어 금지(쉬운 말), 한 사실은 한 번만. "모니터링·주시"로 끝내지 말고 "지금 정할 것 / 조건 → 행동 / 하지 않을 것" 꼴로.
- 모양: 이름표(제목)는 한 줄에 따로 **대괄호 + 굵게** — `[미국]` 꼴(2026-11-17 사용자: "이런 제목은 [미국] 이런 식으로 하고 볼드체로 해"), 내용은 그 아래 글머리 줄. **글머리표는 `*`** — 사용자: "- 는 마이너스랑 헷갈리니까 * 로 하자"(숫자가 많은 글에서 하이픈 글머리 금지). 덩어리 사이에는 가로줄(`──────────────`) 구분선 — "줄은 저거 좋아". **긴 줄표(—)도 쓰지 않는다** — 2026-11-17 사용자: "긴 대쉬도 헷갈리는데, 콜론으로 하면 어때?" (음수 앞 마이너스와 겹쳐 보임). 설명을 덧붙일 때는 콜론, '그래서'의 뜻이면 화살표(→), 범위는 `~`, 빈 칸은 `없음`. 사용자에게 보여 주는 시안·표에서도 같은 원칙.
- **이름표·신호 이름은 그 낱말만 보고 뜻을 알 수 있어야 한다** (2026-11-17 사용자: "지켜보기라는 말이 무슨 의미인질 잘 모르겠다" / "지난번 본 것 — 무슨 의미인지" / "🟡 이유 — 뭐에 대한 이유? 밑에 내용만으로는 맥락이 잘 이해가 안 됨"). 새 이름표를 지을 때 "처음 보는 사람이 이 말만 보고 무엇에 대한 칸인지, 왜 이 숫자가 여기 있는지 아는가"를 확인한다. 줄여 쓴 말("이유", "본 것")은 무엇의 이유인지·무엇을 봤는지가 빠져 뜻이 안 통한다 — 대상을 이름표에 넣고, 숫자에는 기준을 같이 적는다. 말을 바꿀 때는 대안 여러 개 + 권고안을 먼저 보여 주고 사용자가 고른다. 2026-11-17 확정: 🟡 = **주의**(🟢 평소대로·🔴 꼭 확인), `[지난 리포트의 조건 → 결과]`, `[신호가 🟡인 이유]` + 줄마다 "실제 값: 기준"(예: `미국 반도체지수 -5.3%: -3% 넘게 내리면 🟡`).
- 일정·발표 날짜와 "오늘 밤"·"내일 아침"은 **한국 시각 기준**으로 통일(미국 현지 날짜는 괄호) — 같은 일정을 리포트마다 다른 날짜로 적어 사용자가 헷갈릴 뻔했다(2026-11-17).
- 경보 색·등급은 **드물어야 믿는다** — 기준을 숫자로 정해 코드가 판정하고, 과거 데이터에 대입해 빈도를 확인한 뒤 제안한다. 🔴은 "정말 주의"에만.
- 숫자·날짜·요일·색은 코드가 한 출처에서 계산하고 AI는 글만 쓰게 설계한다([[feedback-single-source-no-hand-copies]]와 같은 방향).
- 형식을 바꿀 때는 발송 없는 시험 결과를 실제 산출물로 먼저 보여 주고 적용한다. 실발송 전에는 발송 경로의 실패 처리(재시도·일부만 도착)를 따로 확인한다.

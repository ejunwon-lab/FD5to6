사용자가 받는 리포트·알림(텔레그램 등)은 **맨 위 요약만 읽어도 끝나게** 쓴다: 무슨 일이었나 한 줄 → 내 숫자 → 왜 → **그래서 뭘 할지(최대 3줄)**. 근거·표는 뒤로(별도 메시지) 보낸다.

**Why:** 2026-11-16 사용자: "리포트가 너무 복잡해서 읽기가 힘들어. 두괄식으로 하루를 요약하는 부분을 강화해. 한눈에 그날의 상황을 파악하기 쉽고, 그래서 뭘 해야겠다는 생각을 하게 유도하란 말이야." / "빨간불은 뭔가 정말 내가 어텐션해야하는구나라고 생각하도록 만들 때 사용해." 같은 날 아침 리포트는 AI가 숫자를 직접 계산하다 방향이 반대인 값을 내보냈다.

**How to apply:**
- 리포트·알림 문구나 지시문을 만들고 고칠 때: 첫 줄에 결론, 한 줄에 숫자 2개까지, 증권가 용어·영어 약어 금지(쉬운 말), 한 사실은 한 번만. "모니터링·주시"로 끝내지 말고 "지금 정할 것 / 조건 → 행동 / 하지 않을 것" 꼴로.
- 모양: 이름표는 한 줄에 따로 굵게, 내용은 그 아래 글머리 줄. **글머리표는 `*`** — 사용자: "- 는 마이너스랑 헷갈리니까 * 로 하자"(숫자가 많은 글에서 하이픈 글머리 금지). 덩어리 사이에는 가로줄(`──────────────`) 구분선 — "줄은 저거 좋아". 사용자에게 보여 주는 시안·표에서도 같은 원칙.
- 경보 색·등급은 **드물어야 믿는다** — 기준을 숫자로 정해 코드가 판정하고, 과거 데이터에 대입해 빈도를 확인한 뒤 제안한다. 🔴은 "정말 주의"에만.
- 숫자·날짜·요일·색은 코드가 한 출처에서 계산하고 AI는 글만 쓰게 설계한다([[feedback-single-source-no-hand-copies]]와 같은 방향).
- 형식을 바꿀 때는 발송 없는 시험 결과를 실제 산출물로 먼저 보여 주고 적용한다. 실발송 전에는 발송 경로의 실패 처리(재시도·일부만 도착)를 따로 확인한다.
- 기준·설계: `docs/plans/2026-11-16-리포트-요약우선-신호등.md`, 기준 숫자는 `.github/scripts/signal_rules.py`.

## 설계 점검
1. **외부 동작 가정**
   - 워크플로의 이메일 단계는 `continue-on-error: true`이고 뒤 단계가 그 결과를 쓰지 않는다 → 원문 확인(주간 job에서 같은 삭제를 실제 러너로 검증함).
   - 지금도 메일은 한 통도 안 나간다(10/9~11/13 로그 전부 권한 오류) → 제거로 사용자가 잃는 동작 없음.
   - manifest에서 스코프를 **빼는** 것은 재승인을 요구하지 않는다(소유자의 기존 승인이 더 넓거나 같음 — 지금 소유자는 `send_mail`을 승인하지 않은 상태라 뺀 뒤의 다섯 개가 곧 승인 범위) → **[실환경 검증 필요]** 배포 직후 30분 틱 로그(`tgChainFallback:`)와 5분 신호 로그(`tgPushPnL:`)가 계속 찍히는지. 끊기면 manifest를 되돌려 재배포.
   - 앱(scripts.run)은 스크립트의 스코프가 줄어드는 쪽이라 영향 없음 — 클라이언트 토큰에는 원래 `send_mail`이 없다.
   - `deleteProperty`는 지정 키만 지운다 → 정규식 `^email_(count(_\d{4}-\d{2}-\d{2})?|disabled|last_(us|kr)_(subj|ms))$`에 맞는 키만.
2. **과거 부류** (`errors.md`)
   - 5월 "oauthScopes 명시 → 재승인 필요"(스코프를 **더한** 경우) → 이번은 빼는 쪽이지만 같은 영역이라 배포 직후 로그로 확인하고 되돌림 경로를 준비.
   - 11/10 앱 404(소유자 아닌 계정 저장) → push_safe(소유자 토큰) + 저장 계정 재확인.
   - "head와 배포 버전은 별개" → 새 버전 + 고정 배포 3개 갱신, 버전 소스에서 삭제 확인.
   - 11/13 속성 누적 → 이메일 경로에 묶어 둔 정리가 사라지므로 정리를 매일 갱신으로 옮김.
3. **추론 vs 실환경**
   - 머리로(스텁 실행): 분기 삭제 뒤 다른 action 불변, 삭제한 함수 참조 0, 속성 정리 대상 한정, 정리 실패가 갱신을 막지 않음.
   - 실환경에서만: 스코프 삭제 뒤 트리거·웹앱 실행 지속(로그), 월요일 08:05·17:05 리포트가 이메일 단계 없이 텔레그램 발송·커밋, 속성 정리 건수(17:30 로그).
4. **상대 시스템** — GAS 웹앱 호출 하루 2건 감소. 외부 호출 추가 없음.
5. **검증**
   - 자동: `node --check` 전 파일 · 삭제한 이름 grep 0 · 스텁(`doPost` 분기, 속성 정리) · YAML 문법과 job별 단계 구성(us 11→10, kr 12→11, 이메일 단계 0) · 배포 후 더미 secret POST · 버전 소스에 `MailApp`·`emailReport` 없음 · 30분 틱/5분 신호 로그.
   - 사용자: 월요일 텔레그램으로 US(08:05)·KR(17:05) 리포트가 평소처럼 오는지.

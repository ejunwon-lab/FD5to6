# 설계 노트 — Today 뉴스 패널 + 이벤트 캘린더 (2026-08-06)

/design-check 산출물. 대상: GAS 신규 `newMobileGetNews`(외부 API 호출 추가) + 데스크 NewsPanel·EventsPanel.

## 결정 요약

- **KR 뉴스**: `m.stock.naver.com/api/news/stock/{6자리코드}` (무키 JSON) — **로컬 실측 완료**: `items[].titleFull/title·officeName·datetime(YYYYMMDDHHmm)·mobileNewsUrl(기사 직링크)` 확인
- **US 뉴스**: `api.stock.naver.com/news/worldStock/{SYM}.O` (무키 JSON, **한국어 번역 뉴스**) — 실측 완료: `tit·ohnm·dt(YYYYMMDDHHMMSS)`. 당초 후보였던 Yahoo RSS는 **실측 결과 사망**(sad-panda 에러 페이지) → 네이버 단일 소스로 변경
- **US 기사 직링크 없음** — `news/worldStock/{oid}/{aid}` 리다이렉트가 기사 아닌 일반 flashnews로 감(실측) → US 항목 링크는 종목 뉴스탭 `m.stock.naver.com/worldstock/stock/{sym}/news`으로 폴백
- **8-2 US 실적일**: Yahoo quoteSummary 실측 → `Invalid Crumb`(2023년부터 쿠키+크럼 필수). 크럼 댄스는 취약 → **보류**, 소스 재검토 후 별도 진행
- **8-1 매크로 캘린더**: 외부 API 0개 — FOMC·CPI·금통위는 공표 일정을 웹 검증해 정적 데이터로, 선물옵션 만기는 규칙 계산(KR 동시만기 3·6·9·12월 둘째 목요일, US 트리플위칭 셋째 금요일). 클라이언트 전용이라 게이트 비대상이나 **날짜는 반드시 공식 소스 웹 검증 후 기입**(암기 기입 금지)
- **캐시**: GAS CacheService 30분(`news_v1`) — 전 클라이언트 공유. 쿼터: 보유 ~30종목 × 캐시미스당 1fetch ≈ 최대 ~1.5k/일 « UrlFetch 2만/일
- **아키텍처 원칙 유지**: 클라는 GAS만 호출(scripts.run OAuth 전용, doGet 아님 — SystemStatus와 동일 패턴). 시트 신설 없음(상태/이력 해당 없음 — 캐시는 휘발)

## 1. 외부 동작 가정

- 네이버 국내 종목뉴스 JSON 스키마 → **로컬 curl 실측 확인** (2026-08-06)
- 네이버 해외 종목뉴스 JSON 스키마 → **로컬 curl 실측 확인**; 접미사 .O/.N 모두 응답 확인, 순차 폴백(.O→.N)으로 방어
- **Google IP(GAS)에서 네이버 API 허용 여부** → `[검증 필요 — 실환경 전용]` 로컬 200 ≠ GAS 200 (errors.md 2026-07-03: 층위 분리 교훈). 배포 후 GAS 실행 스모크로만 판정
- UrlFetchApp 사용 권한 → appsscript.json에 `script.external_request` **이미 명시**(2026-05-28 사고 후) → scope 변경·재승인 불필요

## 2. 과거 부류 (errors.md)

- **"Naver 차단 14일차" (2026-07-03)** — 차단 층위 오진(서비스≠IP≠도구). 회피: GAS 배포 후 GAS 환경에서 직접 스모크 실행, 로컬 결과로 "됨" 판정 금지
- **UrlFetchApp 권한 누락 (2026-05-28)** — oauthScopes 자동 추론이 새 deployment에서 리셋. 회피: 이미 명시된 oauthScopes 무변경, appsscript.json 안 건드림
- **Yahoo 429/차단 다발 (여러 건)** — 회피: Yahoo 의존 자체를 제거(뉴스 네이버 단일화, 실적일 보류)

## 3. 추론 가능 vs 실환경 전용

- 머리로 거름: 캐시 TTL·쿼터 산술, fetchAll 병렬화, HTML 엔티티 제거, 6자리 숫자=KR 판별, muteHttpExceptions 시 개별 실패 무해
- 실환경에서만: ① GAS(Google IP)→네이버 응답 여부 ② 실보유 종목 전수에서 스키마 변형(뉴스 0건 종목 등) → 배포 후 `newMobileGetNews` 1회 실행 + 응답 요약 확인으로 실측

## 4. 검증 방법

- 자동: `push_safe.py`의 node --check → 통과. 배포 후 Apps Script API로 `newMobileGetNews` 실행 → `success:true`, `items.length > 0`, KR 항목 `url`이 `n.news.naver.com`, US 항목 한국어 제목 확인
- 데스크: tsc·vitest·build → Today 우측 "오늘의 뉴스" 패널에 헤드라인 N건
- 사용자: Today 탭 → 뉴스 패널에서 보유 종목 헤드라인·시각·매체명, 탭하면 기사(KR)/종목 뉴스탭(US) 열림. 이벤트 패널에 다음 일정 D-day

→ **게이트: 통과** (잔여 `[검증 필요]` 1건은 배포 직후 GAS 스모크로 실측 — 실패 시 items:[] 무해 degrade)

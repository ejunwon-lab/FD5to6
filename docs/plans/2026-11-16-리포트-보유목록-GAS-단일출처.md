# 설계 노트 — 리포트 보유 목록을 GAS 보유현황 하나로 (손으로 적은 사본 제거)

- 날짜: 2026-11-16 · 대상: `.github/scripts/kr_close_prefetch.py` · `.github/workflows/market-report.yml`(KR 사전 수집 단계 인자) · 비공개 저장소 `_config/kr-prompt.md`·`weekly-prompt.md`·`kr-theses.md` — CI 파이프라인 변경 → `/design-check` 대상. GAS 코드 변경 없음(재배포 없음).
- 배경: KR·주간 리포트 지시문에 "보유 KRW 종목"이 글자로 적혀 있었고 GAS 보유현황과 연결이 없었다. 매매는 GAS에 기록됐지만 목록은 2026-07-04 이후 한 번도 고쳐지지 않아, 4종목이 어긋난 채(이미 판 3종목이 보유로, 새로 산 1종목이 누락) 약 4개월 리포트가 나갔다. 11/14에 어긋남을 발견하고도 두 목록의 합집합(†)으로 덮어 둔 것이 두 번째 잘못 — 사본을 없애지 않고 사본끼리 맞추려 했다.

## 원칙
**원본이 있는 데이터를 사람이 따로 적어 두지 않는다.** 보유 목록의 원본은 GAS *보유현황* 하나. 지시문·스크립트·문서 어디에도 종목 목록·종목 수를 적지 않는다. 사본이 꼭 필요하면(원본 무응답 대비) 기계가 성공할 때마다 덮어쓰는 캐시로만 두고, 캐시를 썼다는 사실을 결과물에 드러낸다.

## 안
1. 사전 수집 스크립트: 목록 = `portfolioMetrics.krClose.items`(GAS가 보유현황에서 수량>0·국내 형식 코드·시세 대상 분류로 뽑음). 지시문에서 코드를 긁던 `codes_from_prompt`와 합집합(†) 로직 삭제.
2. 표에 `구분` 칸 추가(국내주식/ETF) — `holdings[].category`를 종목명으로 대응(둘 다 같은 시트 B열에서 온 이름이라 정확히 일치). 지시문이 "뉴스 검색 대상 종목"을 나열할 필요가 없어진다.
3. 대체 목록: GAS 무응답이면 `docs/reports/_kr_holdings.json`(비공개 저장소, 스크립트가 GAS 성공 때마다 덮어씀, 리포트 커밋 단계의 `git add -A`가 함께 커밋). 표 머리에 "○○일 기준 사본" 경고 → 리포트에 한 줄.
4. 투자 논리(`kr-theses.md`)는 사용자가 쓰는 글이라 자동화 불가 → 어긋남을 **드러낸다**: 보유 종목의 이름·코드가 논리 파일에 없으면 표 아래 "논리 미등록 n종목" → 리포트 논리 칸에 `(논리 미등록)`. 논리 파일에만 있는 종목은 지시문 규칙으로 무시.
5. 지시문: 목록·종목 수·종목명이 박힌 출력 틀을 전부 "표의 구분" 참조로 교체. 주간 지시문은 `/tmp/weekly/gas_metrics.json`의 `krClose.items`+`holdings`, 실패 시 위 캐시.

## 1. 외부 동작 가정
- `krClose.items`는 잠금 여부·거래일 여부와 무관하게 보유 종목 전부를 준다 → **사실**(`mcKrCloseTable`: 목록은 보유현황에서, 가격만 이력에서. 11/16 장중 실측 14개·`locked:false`).
- `holdings[].name`과 `krClose.items[].name`은 같은 값 → **사실**(둘 다 보유현황 B열 `String(r[1])`. 11/16 실측 14/14 구분 판정, 미상 0).
- 리포트 커밋 단계가 캐시 파일을 함께 커밋 → **사실**(`cd docs/reports && git add -A`). dry_run에서는 커밋 단계가 돌지 않아 캐시가 남지 않음(의도).
- 주간 job도 같은 비공개 저장소를 `docs/reports`에 체크아웃 → 캐시 접근 가능 **[11/22 주간 실행에서 확인]**.
- 워크플로 파일·스크립트는 run 생성 시점 main 기준 → push 뒤 생성되는 17:02 실행부터 적용 → **사실**(GitHub 동작).

## 2. 과거 부류 (errors.md)
- "routine이 지시문을 무시하고 가이드 파일의 옛 값을 씀"(같은 정보가 두 곳 → 충돌) → 이번에도 같은 부류. 목록을 한 곳(표)에만 둔다.
- 공개 로그에 종목명 금지(11/14 설계) → 스크립트 표준 출력은 개수만(`list=gas stocks=n etf=n no_thesis=n`).
- 11/14 합집합(†) 처리 → 사본 유지가 원인을 덮음. 이번에 삭제.

## 3. 추론 가능 vs 실환경 전용
- 머리로 거름: 인자 3개만 주는 옛 호출도 동작(캐시·논리 검사 생략) · GAS 무응답+캐시 없음 → 표에 "가장 최근 KR 리포트의 포트 표를 목록으로, 그 사실을 밝힘" · 가격을 못 받아도 목록 표는 넘김 · 캐시는 GAS 목록일 때만 덮어씀(캐시로 캐시를 덮지 않음).
- 실환경에서만: 에이전트가 바뀐 지시문으로 표의 종목을 전부·그것만 다루는가 → dry_run 1회 + 오늘 17:05 실제 리포트 본문 대조.

## 4. 상대 시스템에서 보이는 것

## 5. 검증 방법
- 자동(로컬, 실제 GAS 응답): ① 정상 → 표 14행·구분 4/10·캐시 생성 ② GAS 실패 → 캐시로 같은 목록 + 경고 문구 ③ 실패+캐시 없음 → 대체 지시 문구 ④ 논리 파일에서 1종목 제거 → `no_thesis=1` ⑤ 인자 3개 호출. `py_compile`, 워크플로 YAML 파싱.
- 실환경: `gh workflow run market-report.yml -f type=kr -f dry_run=true` → 로그 `prefetch: … list=gas stocks=4 etf=10 no_thesis=0` + 본문 포트 표의 종목 = 보유현황. 오늘 17:05 실행도 같은 줄 + 비공개 저장소에 `_kr_holdings.json` 커밋.

# 설계 노트 — 리포트 제목을 대괄호+굵게, 일정 날짜를 한국 시각으로 (2026-11-17)

## 배경

새 모양 첫 실발송(11/17 08:02 US)을 본 사용자 지시.

- **제목(이름표)**: "이런 제목은 [미국] 이런 식으로 하고 볼드체로 해" → `*미국*` 을 `*[미국]*` 로.
- **일정 날짜 기준**: 같은 일정을 11/16 KR은 "11/18 아침(미국 현지 11/17)", 11/17 US는 "11/17(화)"·"오늘 밤"으로 적음 → 한국 시각 기준으로 통일("진행해").
- 같이 받은 것(대안 제시 후 사용자 선택 대기 — 이 노트의 범위 밖): 🟡 "지켜보기"라는 말, "지난번 본 것"이라는 제목, "🟡 이유" 묶음의 제목·내용.

바꾸는 곳: `.github/scripts/`(`signal_rules`·사전 수집 3종·`report_finalize`·`send_telegram`), 비공개 저장소 지시문 3종. GAS·워크플로 파일은 건드리지 않는다.

## 1. 외부 동작 가정

| 가정 | 근거 |
|---|---|
| 텔레그램 옛 Markdown(`parse_mode=Markdown`)에서 `*[미국]*` 은 굵은 글씨 "[미국]"으로 보인다 | 공식 문서(core.telegram.org/bots/api#markdown-style, 11/17 확인): "Entities must not be nested", "Escaping inside entities is not allowed". 공개 해석기 소스(tdlib `td/telegram/MessageEntity.cpp` `parse_markdown`, 11/17 확인): `*` 를 만나면 다음 `*` 까지의 글자를 **그대로** 옮긴다(안쪽의 `[`·`\` 를 해석하지 않음) |
| 굵게 표시 **밖**의 `[글자]` 는 링크 문법으로 읽혀 **대괄호가 조용히 사라진다**(400 오류가 아니다) | 같은 소스: `[` ~ `]` 사이 글자만 옮기고 괄호는 버린다. 뒤에 `(` 가 없으면 글자를 주소로 보고, 주소가 아니면 아무 표시도 붙이지 않는다 |
| 닫는 `]` 가 없는 `[` 는 400(`Can't find end of the entity`) | 같은 소스. 기존의 일반 글 대체 발송 경로로 도착한다 |
| 표시 밖의 `[` 앞에 역슬래시를 붙이면 글자 그대로 보인다 | 공식 문서: "To escape characters '_', '*', '`', '[' outside of an entity, prepend the character '\\'". 글머리 별표(`\* `)가 같은 규칙으로 11/17 실발송에서 통과(`[OK Markdown]` 4/4) |
| 텔레그램 서버가 위 공개 해석기와 같은 방식으로 해석한다 | **[실환경 확인 필요]** — 문서와 소스가 일치하지만 서버 동작은 실발송으로만 확정된다 |
| 지시문에 날짜 규칙을 넣으면 AI가 한국 시각 기준으로 쓴다 | **[실환경 확인 필요]** — 시험 실행 본문으로 확인. 발표 시각(장 시작 전/마감 뒤)은 코드가 알 수 없어 기계 교정 불가 |

## 2. 과거 부류 (`docs/errors.md`)

- **11/16 틀린 요일** — AI가 직접 쓰는 날짜는 지시만으로 못 막았다. → 이번 "어느 나라 날짜인가"도 같은 종류. 요일은 코드가 고치지만 날짜 기준은 코드가 판정할 재료가 없다. 지시문 규칙 + 예시로 줄이고, 근본책은 주간 리포트가 만드는 `_events.md`(한국 날짜 기준 확정 일정표, 11/22 첫 생성). **한계로 남긴다.**

## 3. 추론으로 거르는 것 vs 실환경에서만 아는 것

**시험으로 거름 (발송 전)**
- 제목 모양 강제: 옛 모양 `*미국*`, 별표 없는 `[미국]`, 순서가 뒤집힌 `[*미국*]`, 별표 두 개 `**미국**` → 전부 `*[미국]*`.
- 건드리면 안 되는 줄: 첫 줄(`🟡 *지켜보기* · …`), 근거 통 첫 줄(`📎 *근거* · …`), 글머리 줄(`* …`), 번호 줄, 기울임 줄, 코드블록 안.
- 뼈대 묶음 되돌리기·빠진 묶음 넣기·이유 묶음 인식이 새 제목 모양에서도 그대로 동작.
- 발송 변환 뒤 "화면에 보일 글자"(해석기 이식본): 제목의 대괄호가 남고 굵게 잡히는지, 글머리 별표가 글자로 남는지, 역슬래시가 화면에 새지 않는지, 본문 속 대괄호(`[속보]`)가 사라지지 않는지, 실제 링크 `[글자](https://…)` 는 링크로 남는지.

**실환경에서만**
- 실제 텔레그램 화면의 굵은 대괄호 제목 → 첫 실발송(11/17 17:05 KR) 로그 `[OK Markdown]` + 사용자 눈. 해석 실패 시 일반 글로 도착(`[OK plain fallback]`).
- AI가 새 지시문(대괄호 제목·`<고정>` 표시·날짜 기준)을 따르는지 → 시험 실행 3종(KR·US·주간)의 `finalize:` 줄과 본문.

## 5. 검증 방법

- **자동**: `python3 .github/scripts/tests/test_report_format.py`(새로 만듦) 전부 통과 · 기존 마무리 시험(임시 폴더 32건)을 새 모양으로 고쳐 통과 · `python3 -m py_compile` · 시험 실행 `gh workflow run market-report.yml --ref report-v4 -f type=<kr|us|weekly> -f dry_run=true -f prompt_dir=_config/next` 3종 → `finalize: … action=kept`, 본문 제목이 전부 `*[…]*`, 일정 줄이 한국 날짜.
- **사용자**: 오늘 17:05 KR 리포트(텔레그램) — 제목이 **[내 포트]** 처럼 굵은 대괄호로 보이고, 줄 맨 앞 별표는 글자로 보임.

## 설계 요점

- 제목 모양은 한 곳(`signal_rules.title`)에서 만든다. 사전 수집의 뼈대 묶음·이유 묶음·마무리의 정규화가 모두 이 함수를 쓴다.
- 지시문의 묶음 표시 `[고정]` 은 `<고정>` 으로 바꾼다(대괄호 제목과 헷갈려 본문에 쓰일 위험을 없앤다).
- 발송 때 표시 밖의 `[` 에 역슬래시를 붙인다(실제 링크는 그대로). 제목 정규화가 놓친 경우에도 대괄호가 사라지지 않게 하는 두 번째 안전망.
- 날짜 규칙(지시문 3종 공통): 일정·발표 날짜는 한국 시각. 미국 장 시작 전 발표·경제지표 = 한국 그날 밤, 연준 결과 = 다음 날 새벽, 장 마감 뒤 실적 = 다음 날 아침. 미국 현지 날짜는 괄호에. 어느 쪽 날짜인지 기사로 알 수 없으면 "미국 현지 기준"이라고 밝힌다.

## 무엇을 하나
- 대상: *현재가_이력* 시트의 **2026-09-14(애프터마켓 개설일) ~ 2026-11-12** 거래일 행, **국내 종목 칸**(해외 종목·빈 칸은 그대로).
- 바꾸는 값: 그날 17:30 갱신 때의 가격(애프터마켓 진행가가 섞였을 수 있음) → **그날 정규장 종가**.
- 근거: 잠금 전 마지막 날(11/13)의 기록이 40칸 중 9칸에서 정규장 종가와 달랐다(11/16 아침 대조).
- **범위 밖**: *추이 기록*(일별 총자산·수익률)은 손대지 않는다. 그날그날 계산해 값으로 적어 둔 기록이라, 고치려면 날짜별 보유 수량·환율·대기자금까지 되살려 다시 계산해야 한다(별도 결정).
- 고친 뒤 달라지는 것: *종목지표*의 기간 손익·수익률(1주·1달·1M~1Y), *매도추적* 곡선, 데스크 가격 이력 화면 → 다음 전체 갱신 때 새 값으로 다시 계산된다.

## 방법
- 새 파일 `apps-script-v2/CloseBackfill.js` — 일회성 작업. `scheduledHourlyUpdate`(30분 트리거, 주말에도 돎) 앞머리에서 `cbfTick()` 호출.
- 실행 조건: 상태 속성 `kr_close_backfill_v1`이 없을 때 **한 번만**. 거래일 08:00~20:30에는 미룬다(갱신·잠금과 겹치지 않게). 스크립트 락을 잡고 실행.
- 출처 두 개
  1. **네이버 일별 시세로 되찾은 정규장 종가** = 다음 거래일의 기준가(다음 날 종가 − 다음 날 전일 대비). 리포트 사전 수집(`mkt.official_series`)이 11/16부터 쓰는 방식.
  2. **KIS 일봉 종가**(기간별 시세, 원주가).
- **쓰기 전 검증 (자동 관문)**: 정규장 종가로 이미 확인된 날(11/13 = 아침 대조로 보정된 행, 11/16~ = 잠금된 행)의 시트 값과 두 출처를 대조한다.
  - 네이버 쪽 일치율이 98% 미만이거나 대조 칸이 100칸 미만이면 **아무것도 쓰지 않고 중단**.
  - 종목별로도 본다: 확인된 날에 한 칸이라도 어긋난 종목은 그 종목 전체를 건드리지 않는다.
  - KIS 쪽 일치율이 98% 이상이면 "KIS 일봉 종가 = 정규장 종가"로 보고, **두 출처가 같은 값일 때만** 쓴다. 미만이면(일봉 종가에 애프터마켓이 섞이는 경우) 네이버 값만 쓰되 지금 값과 10% 넘게 다르면 건너뛴다.
- 쓰기: 바꿀 칸이 있으면 먼저 시트를 통째로 복사해 숨긴 백업 시트 `*현재가_이력*_보정전_2026-11-21`을 만든 뒤, 대상 구간을 한 번에 쓴다.
- 결과: 상태 속성(한 칸, 상태)과 로그 `backfill:` 줄(검증 일치 수, 바꾼 칸·같은 칸·건너뛴 칸 수). 🔍 진단 `closeBackfill`.
- 상태 vs 이력: 백업 시트 = 보정 전 **상태 사본**(되돌리기·무엇이 바뀌었는지 비교용). 상태 속성 = 한 칸 덮어쓰기. 새 이력 저장소는 만들지 않는다.

## 설계 점검

### 1. 외부 동작 가정
- 다음 거래일의 기준가 = 그날 정규장 종가 → **사실**: 분봉의 정규장 마감 값과 대조(11/14: 2종목 × 5일 10/10, **11/21: 보유 14종목 × 5거래일 70/70**, 영숫자 코드 ETF 포함). GAS 쪽 아침 대조(KIS 기준가)도 4일 연속 40/40.
- 네이버 `/api/stock/{code}/price?pageSize=60` → 60거래일(8/25~11/20)을 한 번에 줌(로컬 실측), 100은 실패. 부족하면 2쪽을 더 받는다.
- GAS에서 이 주소 접근 → **[실환경 전용]** (GAS는 네이버의 `/basic`·분봉·업종 주소를 매일 받고 있음. 이 주소는 처음). 못 받으면 검증 칸 0 → 중단.
- KIS 일봉 종가가 정규장 종가인지, 애프터마켓 포함인지 → **[실환경 전용 — 모름]**. 그래서 검증으로 가른다(어느 쪽이어도 맞게 동작).
- 기준가는 권리락·분할 등에서 조정된다 → 그런 날은 "다음 날 기준가 ≠ 전날 종가". KIS를 믿을 수 있으면 두 출처 불일치로 걸러지고, 아니면 10% 한도만 남는다(남는 위험: 10% 이내 조정. 두 달·보유 종목 범위에서 드묾).
- `Sheet.copyTo(ss)`·`hideSheet()`·`setValues` 한 번 쓰기 → Apps Script 표준 동작. 트리거 실행에서 UI 없이 동작.
- 30분 트리거는 주말에도 발화 → **사실**(11/15 일요일 18:26·18:56 로그).

### 2. 과거 부류 (`errors.md`)
- 11/16 "네이버 일봉 종가는 애프터마켓 포함값" → 일별 종가를 그대로 쓰지 않고 다음 날 기준가로 되찾는다.
- 11/16 "5거래일 변화율을 하루 등락으로" (필드 뜻을 가정) → KIS 일봉 필드의 뜻을 가정하지 않고 확인된 날로 검증.
- 7/4 직전가 대체 무경고 → 건너뛴 칸 수를 로그·상태에 남김(무음 금지).
- 5/17·6/21 비거래일 행 → 거래일 행만 대상, 행을 새로 만들지 않음.
- 실행 시간 초과(11/21 관찰) → 한 번 실행에 조회 약 80건 + 쓰기 1회(1분 안쪽 예상). 시작할 때 상태를 `running`으로 먼저 적어, 중간에 죽어도 30분마다 되풀이하지 않게.
- "head와 배포 버전은 별개" → 작업은 트리거(원본) 경로에서만 돌지만, 웹앱 고정 배포도 같은 버전으로 맞춘다.
- 11/13 속성 누적 → 상태 속성은 한 칸.

### 3. 추론 vs 실환경
- 머리로(스텁 시험): 대상 구간·열 한정, 검증 관문(전체·종목별), 두 출처 분기, 10% 한도, 백업 1회, 되풀이 실행 방지, 락·시각 조건, 빈 칸·해외 칸 보존.
- 실환경에서만: GAS → 네이버 일별 시세 접근, KIS 일봉 종가의 정체, 실제 바뀌는 칸 수 → 실행 로그 `backfill:` 한 줄로 판정. 중단되면 아무것도 안 바뀐 상태이므로 로그의 사유를 보고 다음 수를 정한다.

### 4. 상대 시스템에서 보이는 것
- 네이버: 종목당 1~2건(약 40~80건), 10건씩 묶어 0.15초 간격, 브라우저 UA. 한 번뿐.
- KIS: 종목당 1건(약 40건), 5건씩 묶어 0.28초 간격(기존 일괄 조회와 같은 속도). 한 번뿐. 공식 API·본인 키.

### 5. 검증 방법
- 자동(배포 전): `node --check` · 스텁 시험(`scripts/gas-tests/` — 저장소에 보관) · 기존 파일 로드 확인.
- 자동(배포 후): 다음 30분 틱 로그 `backfill: done …` 의 검증 일치 수·바꾼 칸 수, 경고 이상 로그 0건, 30분 틱·5분 신호 지속.
- 사용자: 시트 맨 끝의 숨긴 시트 `*현재가_이력*_보정전_2026-11-21` 존재(숨기기 해제로 확인), 🔍 진단 `closeBackfill`.
- 되돌리기: 백업 시트의 대상 구간을 *현재가_이력*에 붙여 넣으면 보정 전 상태.

→ 게이트: **통과** — 실환경 전용 2건은 검증 관문이 자동으로 가르고, 실패 시 무변경.

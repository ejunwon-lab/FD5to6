# 설계 노트 — watchdog 이상 시만 알림 + 월간 통계 (2026-11-01)

## 배경 (사용자 결정)

매일 오는 `🩺 자동화 헬스체크`(✅ 5~6줄)는 봐도 할 일이 없다 → **문제 있을 때만 즉시 알림 + 한 달에 1번 통계**.

실측으로 드러난 판정 기준 결함: 10월 OAuth 테스트 모드 7일 만료로 푸시 poke가 HTTP 403을 받은 구간이 4번(10/5·10/13·10/20·10/27, errors.md 2026-10-26) 있었는데 watchdog은 **전부 ✅**로 통과시켰다 — "발송 ≥1건이면 정상" 기준이라 10/27(평소 20건 → 7건)도 ✅. 즉 지금까지 실장애를 먼저 알린 적이 없다. 알림을 "이상 시만"으로 바꾸려면 이상 판정부터 조여야 한다.

## 데이터 저장소 (신설) — 상태 vs 이력

- `_watchdog/daily.jsonl` = **이력(append)**. 대상일당 1줄, 같은 날짜 재기록은 덮어씀(멱등). 필드: date·dow·trading·chain_alive·push_runs·sent·http_total·http_err·http_403·sheet·reports{US,KR,WEEK}·red[]·warn[]·checked_at.
- "나중에 뭘 보고 싶어질까?" → 월간 통계(이번 목적), 푸시 건수·오류 추이, 리포트 커밋 시각 추이, watchdog 미실행일. 원료가 매일 쌓이게 함.
- 위치: private 리포트 repo — 금액 없음(건수·시각·판정만)이지만 운영 로그라 public main repo 커밋 이력 오염도 피함. 기존 리포트 프롬프트는 `KR-*`·`US-*`만 glob(weekly-prompt 24~25행 확인) → `_watchdog/` 간섭 없음.

## 1. 외부 동작 가정 + 근거

- `REPORTS_DEPLOY_KEY`는 쓰기 권한 → market-report가 같은 키로 매일 push 중(리포트 repo 커밋 작성자 Market Report Bot).
- checkout `ssh-key`는 job 동안 그 경로 repo에 sshCommand 설정 유지 → market-report의 `cd docs/reports && git push` 동일 패턴.
- poke 로그 줄 형식 `HH:MM:SS UTC  poke#N  HTTP=nnn  resp=…` → telegram-push.yml 120행. 스크립트 원문 에코(`HTTP=%s`)는 `[0-9]+` 패턴에 안 걸림.
- 403은 GAS 실행 전 구글 권한 단계 응답 → 휴장·주말 poke에도 찍힘 → 매일 판정 가능(errors.md 10-26: 9/27 토~9/28 일 구간 실측).
- 리포트 repo push 경합: market-report(US 08시·KR 17시·주간 일 13시)와 watchdog(21:1x, 백업 새벽) 시간 분리 + `pull --rebase` 3회 재시도.

## 3. 추론 가능 vs 실환경 전용

- 머리로 거름: 임계값 판정, upsert 멱등, 월말·폴백 판정, 2회 점검 흐름, green/red 분기.
- 로컬 실측(오늘): `WATCHDOG_DATE=2026-10-27` → 🔴 2개(발송 7 < 10, 403 다수) / `2026-10-30` → 🔴 없음. `watchdog_log.py` 합성 데이터로 upsert·due·monthly.
- 임계값 근거(실측 완료): 10/21~10/31 poke 응답 코드 일별 — 정상일 10일 약 2,900회 중 비정상 **0건**, 10/27만 403×53. → ERR_MIN=6(5분 poke 30분 연속 실패)은 정상일 오탐 여유 충분, 10/20(73분 구간 ≈15건)·10/27(53건) 모두 검출. PUSH_MIN=10(평소 18~21건, 수능·연초 10시 개장일도 ≈18건).
- 구현 중 발견(잠복 결함): 휴장 판정이 대상일 run 로그 전체의 skip-holiday를 봐서, 금요일 밤 run의 자정 넘은 토요일 poke가 금요일을 휴장으로 오판(10/30 재현) → 장중(UTC 00~06시) poke만 보도록 수정. 10/9 한글날 장중 skip-holiday 감지 유지 확인.
- 실환경에서만: ① 러너에서 리포트 repo push ② 실제 21:1x chain run이 ✅일 때 무발송 + daily.jsonl 1줄 커밋 ③ 첫 월말(11/30) 통계 발송 → ①은 push 직후 수동 dispatch(dry_run 아님, auto 아님 → 기록 안 함)로는 검증 불가 → **오늘 21:1x 첫 chain run 결과**로 확인, ③은 수동 `monthly=2026-11` dry_run 미리보기로 문구만 선확인.
